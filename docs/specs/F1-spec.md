## F1.3 --- Torque-aware time parametrization (TOPP-RA)

Files: `app/planning/topp.py` (new), `app/planning/shortcut.py`, `app/panels/planning_panel.py`,
`robotics_api/motion.py`, `docs/planning.md`, tests `tests/python/test_topp.py`.

Method (decided, do not change without Opus): TOPP by reachability analysis (Pham & Pham 2018,
"A New Approach to Time-Optimal Path Parameterization based on Reachability Analysis").

1.  Path geometry: q(s), s in [0, 1], from the planned waypoints with a C2 spline that stays inside
    position limits and collision free (reuse the cubic/linear acceptance from `time_parametrize`).
    Grid s_0..s_N, N = 100 default (option `n_grid`), plus q'(s), q''(s) at grid points.
2.  Variables per stage i: x_i = sdot_i^2 >= 0, u_i = sddot_i, with x_{i+1} = x_i + 2 Δs_i u_i.
3.  Constraints per stage, all linear in (u, x):
    -   velocity: q'_j^2 x <= vmax_j^2 for every j;
    -   acceleration: amin_j <= q'_j u + q''_j x <= amax_j;
    -   torque: tau_min_j <= a_j u + b_j x + c_j <= tau_max_j, where (friction off)
        c = RNEA(q, 0, 0), a = RNEA(q, 0, q') - c, b = RNEA(q, q', q'') - c.
        Compute with `cb.inverse_dynamics`; this identity is exact for RNEA (Coriolis is quadratic in qd).
        Viscous/Coulomb friction is NOT linear in x: leave it out and say so in the docs; the result is
        checked afterwards by `check_trajectory` with friction (step 6).
4.  Backward pass: controllable sets K_i = [x_lo_i, x_hi_i] from K_N = {x_N = 0} (rest at end).
    Forward pass: from x_0 = 0, pick the largest u_i so that x_{i+1} lies in K_{i+1} and stage i
    constraints hold (greedy, time-optimal). Each step is a 2-variable LP: solve it with an own exact
    solver (`_lp2d`: enumerate pairwise intersections of the constraint lines plus bounds, keep feasible
    vertices, pick the best; m <= 4*n_dof + 4 constraints → trivial cost). No scipy.
5.  Times: Δt_i = 2 Δs_i / (sqrt(x_i) + sqrt(x_{i+1})) (guard x = 0 at ends). Output a `Trajectory`
    with waypoints at grid points (q(s_i), t_i), interpolation "cubic" with qd from q'(s_i) sqrt(x_i),
    so playback and checks use the existing classes. Infeasible (some K_i empty) → raise
    `PlanningError("torque limits cannot be met on this path at rest-to-rest")` naming the worst stage.
6.  `time_parametrize(..., method="scale"|"topp", n_grid=100)`: default stays "scale" (old behaviour
    unchanged, old tests green). `method="topp"` uses `topp.py`, then runs `check_trajectory` at fine dt;
    any residual violation → scale times by 1.02 up to 20 times (grid discretisation error), report the
    final scale in `TimedPath` notes.
7.  UI: planning panel time-parametrization combo gets "Time-optimal (torque limits)". API:
    `robotics_api.time_parametrize(..., method="topp")`, documented, API version 1.1 → 1.2 (minor, additive),
    regenerate `docs/api-reference.md` with `tools/gen_api_docs.py`.
8.  Tests (`test_topp.py`):
    -   `_lp2d` vs brute-force grid search on 200 random small LPs, same optimum within 1e-9.
    -   1-DOF double integrator (no dynamics), vmax/amax only: TOPP time equals the analytic bang-bang /
        trapezoid time within 1 %.
    -   Planar 2R with gravity, torque limit below the "scale" result's peak: TOPP trajectory has no torque
        violation (`check_trajectory`, friction off) and every stage has one active constraint (time optimality
        signature), duration within 2 % of a fine-grid (N=1000) reference run.
    -   six_dof fixture R7 milestone path with a 40 N·m limit: no violations, duration <= "scale" duration.
    -   Effort limit 10 N·m on six_dof (below static gravity 25.9 N·m) → `PlanningError`, no hang.
    -   Independent check: the tau of the result recomputed with `numpy_ref` dynamics stays within limits
        + 1e-6.
    -   Speed: 7 DOF, N = 100 in < 1 s.
